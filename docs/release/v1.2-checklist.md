# m4shlab v1.2 — maintainer acceptance checklist

Run this by hand before creating the release tag. Record the device, OS and
browser version with every finding. A failed row stops the release until the
cause is understood.

The `Mode` column says what `npm run test:acceptance` already covers:

- `automated` — checked by the runner on desktop.
- `emulated` — checked by the runner in mobile emulation; a device adds value but does not gate.
- `manual` — cannot be checked without a physical device or a human eye.

Pass/Fail cells stay for every row. Confirming an `automated` or `emulated` row
by eye is allowed and encouraged.

## Sign-off

### Order

1. Land the final docs commit.
2. Run the manual rows below on the device.
3. Record the SHA from `git rev-parse HEAD` and the stamp from &lt;html data-build&gt;.
4. Tag exactly that SHA: `git tag -a m4shlab-v1.2 -m "m4shlab v1.2"`
5. `git push origin m4shlab-v1.2`

The order matters because the signed-off SHA and the tagged SHA must be the
same commit; otherwise the sign-off cannot be tied to what was released.
